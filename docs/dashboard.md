# Дашборд (Phase 8, вход — Phase 9)

React + TypeScript + Vite, папка `frontend/`. Работает только через API KörGöz:
своего сервера и базы у дашборда нет.

## Как открыть

1. Собрать один раз (нужен Node.js 22 LTS):

   ```bash
   cd frontend
   npm ci          # зависимости (из package-lock.json, версии закреплены)
   npm run build   # проверка типов + сборка в frontend/dist
   ```

2. Запустить API как обычно (`uvicorn app.main:app`) и открыть
   **http://127.0.0.1:8000/ui/** (корень `/` тоже перенаправляет туда).

API отдаёт собранные файлы сам (`app/api/dashboard.py`). Отдельный веб-сервер не нужен.
Если `frontend/dist` нет, API просто работает без дашборда. Путь к сборке меняется
настройкой `DASHBOARD_DIR`.

Почему `/ui`, а не `/`: страницы дашборда (`/cameras`, `/events`) совпали бы с путями
API, которые отдают JSON.

## Разработка

```bash
uvicorn app.main:app --reload     # терминал 1: API на :8000
cd frontend && npm run dev        # терминал 2: http://localhost:5173/ui/
```

Vite перезагружает страницу при каждом сохранении и проксирует запросы к API
(`vite.config.ts`). Для браузера это один адрес, поэтому CORS не нужен.
Другой адрес API: `KORGOZ_API=http://host:8000 npm run dev`.

CORS (`CORS_ORIGINS` в `.env`) нужен, только если дашборд размещён на другом домене.

## Проверки

```bash
cd frontend
npm run typecheck   # TypeScript strict
npm test            # vitest + Testing Library (API-клиент, график, все страницы с fake API)
```

## Страницы

| Страница | Путь | Что показывает | Данные |
|---|---|---|---|
| Обзор | `/ui/` | камеры онлайн/офлайн, сейчас в кадре, события и визиты за сегодня, состояние системы, последние события | `/health`, `/cameras`, `/analytics/occupancy`, `/events/count`, `/analytics/people-count`, `/events` |
| Камеры | `/ui/cameras` | список камер, статус, локация (меняется на месте), включение, удаление; добавление камер и локаций | `/cameras`, `/locations` |
| Live View | `/ui/live` | поток каждой камеры с рамками и подписями («Track #42» / «Имя 0.87») | `/cameras/{id}/stream` |
| Люди | `/ui/persons` | список, регистрация по фото (с причиной отказа: нет лица, два лица…) | `/persons` |
| Человек | `/ui/persons/{id}` | данные, timeline (время, камера, локация, событие, уверенность), удаление | `/persons/{id}`, `/persons/{id}/timeline` |
| События | `/ui/events` | фильтры: дата/время, камера, локация, человек, тип события; новые сверху; страницы по 50 | `/events`, `/events/count` |
| Аналитика | `/ui/analytics` | визиты, сейчас в кадре, время пребывания, пиковые часы, график по часам, повторные визиты; период 24 ч / 7 / 30 дней | `/analytics/*` |
| Настройки | `/ui/settings` | состояние компонентов, текущие настройки (без паролей и адресов), смена своего пароля | `/health`, `/settings`, `/auth/password` |
| Пользователи | `/ui/users` | только admin: создать, роль, блокировка, сброс пароля, удаление | `/users` |
| Журнал аудита | `/ui/audit` | только admin: кто, когда, откуда и что менял; фильтры по действию и пользователю | `/audit`, `/users` |

Обзор и Live View обновляются каждые 10 с, аналитика — раз в минуту.

## Устройство

```
frontend/src/
├── main.tsx, App.tsx      роутер (basename /ui) и меню
├── api.ts, types.ts       типизированный клиент API, разбор ошибок FastAPI
├── useApi.ts              загрузка данных: состояние, ошибки, автообновление
├── lookups.ts             камеры/локации/люди для фильтров и имён вместо id
├── format.ts              даты, длительности, русские названия событий
├── components/            StatCard, StatusBadge, EventTable, FlowChart, Notice
├── auth.tsx               текущий пользователь и роль (useAuth)
├── pages/                 10 страниц + страница входа
└── styles.css             токены светлой и тёмной темы (по настройке ОС)
```

- Библиотек графиков нет: `FlowChart` — SVG на ~150 строк. Есть подсказка при наведении,
  легенда и переключатель «Таблица».
- Часы на графике показаны в поясе аналитики (`ANALYTICS_TIMEZONE`), даты событий —
  в поясе браузера.
- Статусы всегда показываются значком и текстом, не только цветом.

## Авторизация

- При открытии дашборд вызывает `GET /auth/me`. Без сеанса показывается страница входа.
- Вход ставит HttpOnly-cookie. Её получают и `fetch`, и `<img>` live view (один origin
  с API).
- Любой ответ 401 (сеанс истёк, пользователя заблокировали) возвращает на страницу
  входа: `request()` в `api.ts` шлёт событие `korgoz:unauthorized`, `App` его слушает.
- Роль `user` видит всё, но без кнопок изменения (добавить/удалить камеру, регистрация
  людей и т. п.). Разделы «Пользователи» и «Журнал аудита» видит только admin.
  Скрытие кнопок — удобство: права проверяет API ([security.md](security.md)).
- Vite dev server проксирует API на тот же origin, cookie работает и там.
